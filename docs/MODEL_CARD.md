# Карточка модели: раннее выявление риска незачёта (edurisk)

Статус: **исследовательский прототип**. Все числа получены на синтетических данных; на реальных студентах модель не проверялась.

## Назначение
Подсказка преподавателю: каким студентам стоит уделить внимание на неделях 4–8 семестра, пока ещё можно помочь. Прогноз — вероятность не пройти промежуточную аттестацию с первой попытки (незачёт, оценка «2», недопуск, отчисление).

**Не предназначена** для: отчисления, стипендиальных и иных решений о студенте, оценивания преподавателей, автоматических действий без участия человека, использования вне вуза-источника данных без повторной проверки.

## Данные и признаки
- Источник сейчас: симулятор (`edurisk.simulate`, `edurisk.world`) с известной причинной моделью; адаптер OULAD написан, на настоящих файлах не проверялся. См. `DATA_SHEET.md`.
- Признаки недели *t* считаются только по данным первых *t* недель; история — только по итогам прошлых семестров. Защита от утечки проверена тестами.
- Группы признаков: активность в LMS, контрольные точки, история прошлых семестров, исходные данные (балл ЕГЭ, нагрузка, занятость), особенности дисциплины. Пол и происхождение в признаки **не входят** и используются только для анализа справедливости.

## Модели
Логистическая регрессия (elastic net), градиентный бустинг, стекинг, изотоническая калибровка на валидации. Разбиение по студентам: 60/20/20. Для оценок 2–5: каскад Фрэнка–Холла и многоклассовые модели; конформные наборы оценок (порог по классам).

## Качество (синтетика, 5 миров по 2000 студентов; подробности в `stage4_results.txt`, `stage5_results.txt`)
- ROC-AUC 0,85 (неделя 4) и 0,92 (неделя 8); простое правило «2 проваленные контрольные подряд или средний балл < 3» даёт 0,66 и 0,70.
- Калибровка: ECE около 0,01–0,02.
- Бустинг и логистическая регрессия статистически неразличимы; производные признаки (серии провалов и т. п.) прироста точности не дали (`stage6_results.txt`).
- Конформные наборы оценок: 90% покрытие, в том числе для редкого класса «2», при пороге по классам.

## Объяснения
Вклады пяти смысловых групп (точный Шепли), вклады признаков логистической модели, сценарий «что если». На симуляторе объяснения указывают на группу, через которую проявляется заложенная причина (потеря интереса: доля активности 0,63 против 0,21 у студентов с низкими способностями). Это описание **модели**, а не причин в реальной жизни. Причина, ещё не проявившаяся в данных, объяснением не найдётся. См. `stage6_explain_refined.txt`.

## Справедливость (`stage7_results.txt`)
При отсутствии смещения измерения (S0) разности по полу и происхождению незначимы. При смещении измерения (S3: студенты из других регионов реже заходят в LMS при той же вовлечённости) модель чаще помечает эту группу: ложные тревоги +2,7 п. п. (95% ИИ +1,6…+3,9), доля помеченных +3,2 п. п. Пороги по группам, выравнивающие долю ложных тревог, снимают разницу почти без потери общей точности — но использование атрибута группы при решении требует отдельного правового и этического обоснования и по умолчанию выключено.

## Ограничения и риски
- Самосбывающийся ярлык: пометка может изменить отношение к студенту. Поэтому формулировки нейтральные («зона внимания»), решения принимает человек, у преподавателя есть кнопка «не согласен», все просмотры и несогласия пишутся в журнал.
- Обратная связь: если вмешательство изменит поведение, распределение данных сменится; модель нужно регулярно переобучать и перекалибровать (сдвиг когорты ухудшает калибровку).
- Данные вуза могут отличаться от симулятора сильнее, чем любой из проверенных сценариев.
- Эффект вмешательств не оценивался; «что если» — сценарий о модели, не обещание результата.
- Поздние недели (12+) почти тривиальны, польза — на неделях 4–8.

## Юридическое
Обработка персональных данных студентов (152-ФЗ): основание, срок хранения, права субъектов, оператор — согласовать с ответственным за ПДн вуза. Технические меры в проекте: минимизация, псевдонимизация, роли, журнал. Юридическую экспертизу они не заменяют.
