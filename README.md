# edurisk

*[English version](README.en.md)*

Раннее выявление студентов группы риска по недельным данным LMS: временные ряды, производные признаки, объяснимость для преподавателя, этические ограничения. Проект ведётся как выпускная квалификационная работа; **готовы все этапы плана** (данные, признаки, симулятор, хранилище и адаптер OULAD, модели риска, оценки 2–5 и допуск, объяснимость, справедливость и приватность, интерфейс преподавателя); что не проверено на реальных данных и что не установлено в среде разработки — в разделе «Ограничения». План и статусы: [PLAN.md](PLAN.md); для текста работы: [docs/VKR_OUTLINE.md](docs/VKR_OUTLINE.md).

## Что уже есть

- **`edurisk/simulate.py`: симулятор когорты с известной причинной моделью.** Скрытые способности и мотивация, «потеря интереса» в случайную неделю, уход из курса, контрольные точки, исход. Нужен, чтобы проверять, находят ли модель и объяснения то, что в данные заложено. На реальных данных этого проверить нельзя.
- **`edurisk/features.py`: 20 недельных признаков** (статика, сырые агрегаты, производные: серия подряд проваленных контрольных, тренд активности, EWMA, недель с последнего входа, изменение балла, активность относительно когорты).
- **`edurisk/curriculum.py` и `edurisk/world.py` (этап 2): многодисциплинарный симулятор.** Учебный план из нескольких семестров с формами контроля РФ: зачёт (зачёт/незачёт), дифзачёт, экзамен и курсовая (оценка 2–5), З.Е. и сложность дисциплины, пререквизиты. Студент проходит семестры подряд: мотивация дрейфует, вовлечённость общая для дисциплин семестра плюс «интерес» к каждой, проваленные контрольные точки снижают вовлечённость дальше (обратная связь), допуск к аттестации по доле сданных контрольных, недопуск и отчисление = «2», пересдача хранится отдельно и в метку не попадает. Сценарии: S0 гладкий, S1 пороговая обратная связь («выученная беспомощность»), S2 сдвиг когорты, S3 смещение измерения по группе (для справедливости), S4 потери данных. `World.course_view(c)` отдаёт дисциплину в формате этапа 1, `World.history_before(s)` — только итоги предыдущих семестров, `World.labels()` — целевые T1 (провал), T2 (оценка), T3 (допуск).
- **`edurisk/store.py`, `db/schema_pg.sql`, `docker-compose.yml` (этап 3): хранилище.** Схема в 3НФ (студенты, дисциплины, расписание контрольных, зачисления с итогами, недельная активность, контрольные, журнал действий), ограничения на уровне БД (формы контроля, оценки 2–5, внешние ключи). `save_world` / `load_world` — точный круговой обмен с `World`; `activity_until(conn, course, week)` — срез по неделе на уровне SQL; `log_action` — журнал «кто что смотрел». Скрытая «истина» симулятора в БД не хранится. Тесты идут на SQLite (стандартная библиотека); DDL для PostgreSQL генерируется тем же кодом (`python scripts/make_schema.py pg`).
- **`edurisk/oulad.py`: адаптер открытого набора OULAD** (`python scripts/load_oulad.py <папка> [БД]`). Написан по описанию набора и проверен на синтетическом наборе в его формате с ручным расчётом недель, дней активности, кликов, просрочек, перенесённых баллов; **на настоящих файлах не запускался**.
- **`dataset.py`, `costs.py`, `metrics.py`, `models.py`, `experiment.py` (этап 4): модели риска провала (T1).** Выборка «студент × дисциплина × неделя» (признаки этапа 1 + история прошлых семестров + З.Е. и форма контроля), разбиение 60/20/20 строго по студентам. Модели: правило «2 проваленные подряд или средний балл < 3», логистическая регрессия elastic net, бустинг, бустинг с ЗЕТ-весом и весом класса, изотоническая калибровка на валидации, стекинг (веса только на валидации). Метрики: ROC-AUC, PR-AUC, Brier, ECE, ожидаемая стоимость с ЗЕТ-весом, взвешенный recall в списке внимания (верхние 10% по p·w·k). Парный бутстрэп по студентам с поправкой Холма.
- **`ordinal.py`, `conformal.py`, `experiment5.py` (этап 5): оценка 2–5, допуск, конформные наборы.** T2: каскад Фрэнка–Холла (три бинарные модели P(≥3), P(≥4), P(=5) с изотонической калибровкой и принудительной монотонностью), многоклассовые logit и бустинг, база по долям классов. Решение по матрице стоимости (завышение оценки в `asym` раз дороже занижения, умножается на ЗЕТ-вес дисциплины): оценка с минимальной ожидаемой стоимостью вместо argmax. T3: вероятность недопуска. Конформные наборы оценок с порогом по валидации, общим и по истинным классам.
- **`explain.py` (этап 6): объяснимость.** Точный интервенционный Шепли по пяти смысловым группам признаков (активность, контрольные точки, история, исходные данные, дисциплина) для любой модели; точные вклады признаков логистической модели; «что если» (замена группы типичными значениями); групповая перестановочная важность; нейтральные тексты для преподавателя («зона внимания»). SHAP-библиотека в среде не устанавливалась, поэтому реализовано без неё.
- **`fairness.py`, `privacy.py`, `docs/MODEL_CARD.md`, `docs/DATA_SHEET.md` (этап 7): справедливость и этика.** Метрики по группам (доля помеченных, TPR, FPR, AUC, ECE), разности с бутстрэп-интервалами, пороги по группам для выравнивания ложных тревог, псевдонимизация (HMAC), удаление чувствительных столбцов, k-анонимность, роли и права, карточка модели и паспорт данных.
- **`service.py`, `app.py`, `scripts/run_demo.py` (этап 8): интерфейс преподавателя.** Список риска по дисциплине с приоритетом (вероятность × З.Е.-вес × стоимость), карточка студента (текстовое объяснение, графики входов и контрольных, вклады групп, «что если»), кнопка «не согласен», журнал просмотров и несогласий, роли teacher / methodist / admin, подписанные токены, CSRF-защита форм, экранирование HTML, графики встроенным SVG без JavaScript. Веб-слой на WSGI + jinja2; FastAPI в среде не установился, логика отделена от веб-слоя (`service.py`) для переноса. Запуск: `python scripts/run_demo.py`.
- **Защита от утечки по построению.** Признаки недели *t* считаются по `cohort.observed(t)`, где будущих данных физически нет.

```python
from edurisk.simulate import simulate
from edurisk.features import build_features

cohort = simulate(1000, seed=0)
X = build_features(cohort, week=6)      # признаки по данным первых 6 недель
y = cohort.outcome                      # True = провалил курс или ушёл
```

## Проверка

`python -m unittest discover -s tests`: 126 тестов (этапы 1–8), около 1,5 минут. Нужны numpy, pandas, scikit-learn.

- Векторизованные признаки сверены на каждой из 16 недель с независимой реализацией «в лоб» (циклы по студентам).
- **Тест на утечку:** все данные после недели *t* заменяются случайными, а исход инвертируется; признаки недели *t* обязаны остаться побитово теми же. Парный тест чувствительности проверяет, что изменение прошлого признаки меняет (иначе тест на утечку ничего бы не значил).
- Серии провалов, пропуск контрольной (считается провалом), EWMA и тренд проверены на примерах, посчитанных вручную.
- `python scripts/mutate.py` вносит в код 103 типичные ошибки (`--targeted` — только отмеченные, с запуском затронутого набора тестов) (сдвиг окна на неделю вперёд, перепутанные знаки, не обнуляющаяся серия, граница допуска, отчисленные продолжают учиться, история захватывает текущий семестр и т. п.); все ловятся (ранние 60 проверены полным набором тестов на момент добавления, поздние 43 — запуском затронутого набора; две мутации этапа 5 — строгая граница конформного набора и калибровка каскада на обучающей выборке — сначала выжили, дописаны тесты; три мутации этапа 4 сначала выжили — ECE при прогнозе 1,0, калибровка на обучающей выборке, обучение без веса класса — и под них дописаны тесты; среди прочего: SQL-срез захватывает лишнюю неделю, перепутаны поля при записи в БД, опоздавшие работы засчитываются, экзамен стал контрольной точкой; одна мутация сначала выжила из-за слабого тестового набора OULAD, набор исправлен). В ходе проверки одна мутация оказалась равносильной исходному коду (удалён избыточный множитель), а другая выжила из-за удачно выбранного α = 0,5, поэтому α изменён на 0,4 и добавлен ручной пример.

### Что проверяют тесты этапа 2

Допуск пересчитан независимой реализацией «в лоб» по случайным парам студент-дисциплина; согласованность оценок, зачётов, недопуска, отчисления и пересдач; нет активности после ухода; доли исходов в реалистичных границах (провалов около 19%, отчислено около 14% за 4 семестра, допуск около 87%); причинные знаки (способности, сложность курса) и **восстановление заложенного коэффициента пререквизита** регрессией по скрытым переменным; история не видит текущий и следующие семестры; признаки этапа 1 на `course_view` не зависят от данных после недели *t*; у каждого сценария проверен его собственный эффект (скачок обратной связи S1, недообученная на когорте 0 модель недооценивает риск когорты 1 в S2, смещение логинов на 25% без смещения успеваемости в S3, потеря записей без изменения исходов в S4). Две первые версии тестов S2 и пререквизита оказались неверными, и их пришлось переписать: гипотеза «связь активности с исходом слабеет» не подтвердилась (она даже усилилась из-за роста доли провалов), поэтому проверяется то, что действительно важно, — рассогласование калибровки.

## Результат этапа 2

`python scripts/stage2_check.py` ([docs/stage2_results.txt](docs/stage2_results.txt)): бустинг на признаках этапа 1, обучение на одном seed, тест на другом. ROC-AUC по формам контроля на неделях 4 / 8 / 12: зачёт 0,83 / 0,91 / 0,99; дифзачёт 0,84 / 0,94 / 0,99; экзамен 0,79 / 0,90 / 0,98; курсовая 0,84 / 0,94 / 0,99. Сдвиг когорты (S2, экзамен): модель, обученная на когорте 0, на новой когорте даёт почти тот же AUC (0,77 / 0,90 / 0,98), но занижает долю риска (прогноз 0,19–0,25 при факте 0,28), то есть **ранжирование сохраняется, ломается калибровка**, так что пороги придётся пересчитывать.

**Оговорка:** метка «не прошёл с первой попытки» включает недопуск, а допуск почти полностью определяется контрольными точками, уже известными к 12-й неделе. Поэтому AUC около 0,99 на поздних неделях тривиален; содержательны недели 4–8, где AUC 0,79–0,94.

## Результат этапа 4

`python scripts/stage4_experiment.py` (около 3 минут; полный вывод в [docs/stage4_results.txt](docs/stage4_results.txt)). Пять миров по 2000 студентов, k = 3 (пропуск провала в 3 раза дороже ложной тревоги), ЗЕТ-вес γ = 2. Среднее по пяти мирам (в файле есть и другие метрики и разброс):

| неделя | модель | ROC-AUC | стоимость |
|---|---|---|---|
| 4 | правило | 0,660 | 0,481 |
| 4 | логистическая регрессия | 0,851 | 0,348 |
| 4 | бустинг + калибровка | 0,848 | 0,347 |
| 4 | стекинг | 0,852 | 0,348 |
| 8 | правило | 0,702 | 0,449 |
| 8 | логистическая регрессия | 0,924 | 0,251 |
| 8 | бустинг + калибровка | 0,922 | 0,249 |
| 8 | стекинг | 0,924 | 0,249 |

(Если никого не помечать, стоимость 0,647; если помечать всех, 0,892.)

Выводы, включая неприятные:

1. **Обученные модели намного лучше правила** (разность ROC-AUC +0,19 на неделе 4 и +0,22 на неделе 8, Холм p < 0,05; стоимость ниже на 0,13 и 0,20).
2. **Бустинг не лучше логистической регрессии.** Разности порядка 0,002–0,003 AUC и статистически незначимая разность стоимости. Причина в симуляторе: зависимость от признаков почти аддитивная, и нелинейности бустингу брать негде. На реальных данных вывод может быть другим.
3. **Обучение с ЗЕТ-весом не дало выигрыша по стоимости** (разность +0,002, p = 1). Для бинарной постановки это ожидаемо: вес дисциплины умножает обе ошибки, и порог решения 1/(1+k) от З.Е. не зависит. Вес меняет итоговую оценку и порядок в ограниченном списке внимания; на самой модели он почти не сказывается. Идея ЗЕТ-взвешивания из прототипа сохраняет смысл для многоклассовой постановки (этап 5), но не здесь.
4. **Калибровка обязательна после взвешенного обучения:** без неё ECE бустинга с весами 0,12 (неделя 4) и 0,08 (неделя 8), после изотонической калибровки 0,015 и 0,011. Без весов калибровка почти ничего не меняет, а PR-AUC слегка падает из-за склейки соседних значений.
5. **Стекинг** даёт ROC-AUC на 0,003 выше бустинга (значимо), но относительно логистической регрессии разность незначима. Игра не стоит свеч.
6. Чувствительность к k и γ: порядок моделей сохраняется во всех девяти сочетаниях.

**Сравнение с прототипом.** Исходников прототипа нет, поэтому его метрики (Macro-F1 0,525, recall класса «2» 0,62) нельзя пересчитать на этих данных: другие данные, другая постановка. Роль прототипа здесь играет правило-основа; честное сравнение возможно только после появления реальных данных или восстановления прототипа по статье.

## Результат этапа 5

`python scripts/stage5_experiment.py` (около 10 минут; [docs/stage5_results.txt](docs/stage5_results.txt)). Пять миров по 2000 студентов; T2 — только дифзачёты, экзамены и курсовые (у зачётов оценки нет), в классе «2» около 20% (включая недопуск и отчисление). Среднее по мирам; рядом метрики прототипа по смыслу (Macro-F1, recall класса «2»), но **на других данных, это не сравнение**:

| неделя | модель (argmax) | QWK | MAE | Macro-F1 | recall «2» | recall «2» при решении по стоимости |
|---|---|---|---|---|---|---|
| 4 | долевая база | 0,00 | 0,83 | 0,14 | 0,00 | 0,00 |
| 4 | каскад + бустинг | 0,63 | 0,54 | 0,54 | 0,51 | 0,66 |
| 8 | долевая база | 0,00 | 0,83 | 0,14 | 0,00 | 0,00 |
| 8 | каскад + бустинг | 0,73 | 0,44 | 0,61 | 0,68 | 0,80 |
| 12 | каскад + бустинг | 0,86 | 0,28 | 0,74 | 0,88 | 0,94 |

1. **Решение по минимуму ожидаемой стоимости резко повышает recall двоек** (на неделе 4 с 0,51 до 0,66, на неделе 8 с 0,68 до 0,80) и снижает стоимость на 0,33–0,43 (интервалы далеки от нуля). Оговорка: стоимость оценивается той же матрицей, по которой принято решение, поэтому её снижение ожидаемо; метрично-независимый эффект — именно рост recall двоек за счёт более осторожных оценок.
2. **Каскад Фрэнка–Холла НЕ лучше обычной многоклассовой модели.** По логарифмической потере он хуже на 0,01–0,03 (значимо), по стоимости разница незначима. Порядковая структура не окупилась на этом симуляторе. Это неожиданно, и вывод стоит проверить на реальных данных.
3. **ЗЕТ-взвешенное обучение каскада стоимость не снижает** (разности в пределах шума), как и на этапе 4. Влияние З.Е. остаётся в оценке стоимости и очерёдности списка внимания, а не в обучении.
4. **Конформные наборы с одним общим порогом дают в среднем нужные ~90%, но недопокрывают редкие и «средние» классы:** класс «2» 0,81 и класс «3» 0,79 на неделе 4. Порог по классам исправляет это (0,94 / 0,89 / 0,90 / 0,90 по классам) ценой набора побольше (2,6 оценки против 2,3 на неделе 4, 2,1 против 1,9 на неделе 8). Для системы предупреждения нужен именно вариант по классам.
5. **Сдвиг когорты (S2) покрытие не сломал** (0,918 против 0,900 у «своей» когорты; для класса «2» 0,90). Я ожидал падения. Сдвиг в симуляторе умеренный и смещает вероятности равномерно, поэтому гарантия сохранилась; на реальных данных с другим характером сдвига её нужно перепроверять.
6. **T3, недопуск:** ROC-AUC 0,87 (неделя 4), 0,94 (неделя 8), 0,99 (неделя 12), калибровка хорошая (ECE около 0,01). На неделе 12 это почти детерминированное следствие контрольных точек, как и на этапе 4.

## Результат этапа 6: абляция признаков и объяснимость

`scripts/stage6_experiment.py` ([docs/stage6_results.txt](docs/stage6_results.txt)), `scripts/stage6_explain_refined.py` ([docs/stage6_explain_refined.txt](docs/stage6_explain_refined.txt)).

**Абляция (ROC-AUC, сценарии S0, S1 пороговая обратная связь, S4 потери данных; 4 мира по 1200 студентов).** Наборы: контекст (исходные данные, история, дисциплина), + сырые агрегаты, + производные, всё вместе. Неделя 8, бустинг, S0: контекст 0,776; + сырые 0,921; + производные 0,919; всё 0,922.

1. Поведенческие признаки дают основной прирост (+0,14…+0,16 AUC на неделе 8).
2. **Гипотеза «производные признаки (серии провалов, тренды) повышают точность» не подтвердилась ни в одном сценарии**, включая пороговый S1, где её ожидали: производные без сырых даже чуть хуже сырых (−0,002…−0,008), а добавление к сырым даёт +0,002–0,003 AUC (значимо, но практически ничтожно). Согласуется с результатом этапа 1: бустинг и сам восстанавливает суммы и серии из агрегатов. Производные остаются полезными как **понятные преподавателю** формулировки («3 контрольные подряд не сданы»), но не как источник точности.
3. Объяснения. Первая версия проверки на симуляторе **не подтвердила ожидание**: у студентов с низкими способностями доля поведенческих групп в положительных вкладах оказалась не ниже, чем у студентов с потерей интереса. Причин две. Во-первых, низкие способности проявляются через провалы контрольных (их баллы зависят от способностей), то есть объяснение верно описывает то, что модель видит. Во-вторых, у части «теряющих интерес» спад начинается после недели 8 и в данных ещё не виден. После уточнения (учитывать потерю интереса, только если она уже проявилась): доля группы «активность» 0,63 против 0,21 у студентов с низкими способностями (разность +0,42, ИИ +0,35…+0,49), доля группы «контрольные точки» 0,16 против 0,57 (−0,41). Ещё не проявившуюся причину объяснение найти не может, и это ограничение любого объяснения.
4. Проверка здравого смысла: при перемешанных метках вклады почти пропадают (средний модуль 0,004 против 0,052), корреляция с вкладами настоящей модели −0,10. Групповая важность стабильна при пересборке моделей на бутстрэп-выборках студентов (ранговая корреляция Спирмена 0,87, минимум 0,60); главные группы — контрольные точки (падение AUC 0,167) и активность (0,086).

## Результат этапа 7: справедливость

`scripts/stage7_experiment.py` ([docs/stage7_results.txt](docs/stage7_results.txt)); порог 0,25 (k = 3), неделя 8, 5 миров по 2000 студентов.

- **S0 (смещения измерения нет):** разности по происхождению и полу незначимы (ложные тревоги +0,8 п. п. [−0,6; +2,1] по origin).
- **S3 (студенты из других регионов реже заходят в LMS при той же вовлечённости, на успеваемость это не влияет):** доля провалов в группах одинакова (17,7% и 17,8%), но модель чаще помечает группу other_region: ложные тревоги +2,7 п. п. [+1,6; +3,9], доля помеченных +3,2 п. п. [+0,8; +5,5], найденных провалов +5,0 п. п. По полу различий нет. Модель переносит смещение измерения в смещение решений.
- **Мера:** пороги по origin, выравнивающие долю ложных тревог на валидации (0,213 и 0,255), убирают разницу (ложные тревоги +0,3 п. п. [−0,9; +1,4]) почти без потери общей точности (TPR 0,775 → 0,774, FPR 0,103 → 0,101). Но использование атрибута группы при принятии решения требует отдельного правового и этического обоснования, поэтому по умолчанию мера выключена. Устранение источника смещения (учёт различий в способах работы с LMS) предпочтительнее.

## Ограничения

- Всё, что здесь измерено, получено на **синтетических данных**. Они показывают работоспособность конвейера, а не качество на реальных студентах.
- Поздние недели (14–16) почти тривиальны: к ним уходившие студенты уже отличимы по нулевой активности. Ценность для практики имеют недели 4–8.
- Параметры многодисциплинарного симулятора (отчисления около 4% за семестр, допуск около 87%, оценки среди допущенных: 2 — 2%, 3 — 23%, 4 — 46%, 5 — 29%) подобраны по правдоподобию, а не по статистике вуза; их нужно заменить данными кафедры.
- Параметры симулятора этапа 1 подобраны так, чтобы доли провалов (около 26%) и ушедших (около 17%) выглядели правдоподобно, и не оценены по реальной статистике.
- **Не установлены и не использовались:** FastAPI, SHAP, LightGBM, SQLAlchemy, PyTorch (у разработки не было сети): интерфейс сделан на WSGI, объяснения написаны вручную, бустинг — из scikit-learn. Нейросетевые модели (GRU/TCN) не пробовались.
- **Интерфейс — прототип:** вход через подписанные токены вместо OAuth2, секрет в демо-режиме задан в коде, пароля и регистрации нет; браузерный вид проверен только по HTML и SVG, не глазами.
- **PostgreSQL и Docker не проверялись** (нет в среде): схема и `docker-compose.yml` написаны, но не запущены; SQLAlchemy не использован, потому что не установился. Адаптер OULAD не проверен на реальных файлах: в OULAD нет оценок 2–5 и ЕГЭ, дисциплины там — «модуль × семестр» с итогом Pass/Fail/Withdrawn, а «логины» и «минуты» — дни активности и клики.
- Нет сети в среде разработки, поэтому LightGBM, SHAP, FastAPI не использовались и не проверялись; для бустинга взят `HistGradientBoostingClassifier` из scikit-learn.
